# يومي LifeOS — تحديثات أندرويد الأصلية التلقائية
## ويدجتس الهاتف الأصلية — بدون قسم أو زر داخل التطبيق

تطبيق Android الأصلي له اسم الحزمة نفسه `com.yawmilife.app`، ويضم **7 ويدجتس أندرويد أصلية** تُسجّل عبر `AppWidgetProvider` في نظام Android:
لوحة اليوم، الإنتاجية، التخطيط، القراءة والقرآن، الصحة والروتين، شؤون حياتي، والاختصارات.

**إضافة الويدجتس تتم خارج تطبيق يومي:**
1. ارجع إلى شاشة هاتف Android الرئيسية.
2. اضغط مطولًا على مكان فارغ، ثم اختر **الويدجتس / Widgets**.
3. ابحث عن «يومي» أو «YAWMI LifeOS».
4. اختر أي ويدجت واسحبه إلى الشاشة الرئيسية.

تم **حذف زر «▦ الويدجتس» من شريط تطبيق يومي**، وحذف نافذة اختيارها الداخلية، وإزالة قسمي «ويدجتس شاشة الهاتف» و«ويدجتس يومي» القديمين من صفحات ATLAS / JOURNAL / QUEST، وحذف مصدر لوحة الويدجتس القديمة.
النظام الجديد لا يعرض أزرار ربط الويدجت داخل التطبيق.

عند وضع ويدجت يحتاج بيانات حسابك، اضغط عليه من **شاشة هاتف Android** إن ظهرت «اضغط للاتصال بحسابك»، ثم سجّل دخول يومي كالمعتاد. يحاول الربط تلقائيًا بعد اكتمال تسجيل الدخول؛ الويدجت لا يكشف أسماء المهام أو بيانات الحساب الخاصة. وويدجت الاختصارات لا يحتاج ربط حساب لإظهار أزراره.

**مهم:** تنزيل تطبيق الموقع PWA أو «إضافة إلى الشاشة الرئيسية» من Chrome لا يضيف ويدجتس Android الأصلية؛ هذه تحتاج تثبيت APK الموقّع من إصدار يتضمن AppWidgetProvider، وليس APK الإصدار 1.0.0 المنشور قديمًا.
تحديث HTML/JS على GitHub Pages يزيل القسم الداخلي في نسخ الويب، لكنه **لا يضيف ويدجتس أندرويد إلى إصدار APK قديم**.

## حماية التحديث والبيانات

يبقى اسم الحزمة كما هو، وتبقى شهادة توقيع Android الأصلية. لا تحذف التطبيق المثبت عند تنزيل APK موقّع بالتوقيع نفسه؛ ثبّت النسخة الجديدة فوقه. قد يحتاج Android موافقة صريحة على التحديث. لا يمكن فرض تثبيت APK في الخلفية على أجهزة المستخدمين العادية.

GitHub Actions قادر على البناء والاختبار تلقائيًا، لكن النشر الرسمي لتحديثات APK يتطلب إعداد أسرار مفتاح التوقيع الأصلية في GitHub Actions أولًا. لا ينشر المشروع ملف APK موقعًا بشهادة أخرى بدل شهادتك.

## اختبار الجودة

يتحقق `android/qa-launch-smoke.sh` من فتح التطبيق دون انهيار، ووجود المستقبلات السبعة للويدجتس في الحزمة المثبتة، **وعدم وجود نافذة أو زر ويدجتس داخل التطبيق**. اختبارات الويب تتأكد من استمرار مزامنة البيانات في الخلفية دون إنشاء لوحة ويدجتس.

## التحديثات التلقائية المدمجة (قبل النشر على Uptodown)

- تغييرات HTML وCSS وJavaScript تظهر عبر موقع يومي المنشور وتطبيق الـPWA دون تنزيل APK مع كل تعديل.
- التطبيق الأصلي `com.yawmilife.app` يراقب أحدث إصدار APK موثوق تلقائيًا عند فتحه أو العودة إليه، ويجدول فحصًا في الخلفية كل 30 دقيقة تقريبًا باستخدام WorkManager. أندرويد قد يؤخر المهام في الخلفية بسبب البطارية أو الشبكة؛ التوقيت ليس لحظيًا مضمونًا.
- بعد العثور على إصدار أحدث يتم تنزيل APK تلقائيًا باستخدام DownloadManager. عند اكتمال التنزيل تبدأ فحوصات SHA-256 والتوقيع الأصلي ورقم الإصدار واسم الحزمة، ولا تثبت أي نسخة تخالفها.
- عندما يسمح Android 12 فأحدث بخاصية `PackageInstaller.USER_ACTION_NOT_REQUIRED` لتحديث التطبيق نفسه، تُطبّق النسخة من دون تأكيد إضافي. وإلا يستخدم التطبيق شاشة موافقة Android الرسمية؛ لا يمكن تجاوز حماية النظام.
- لا توجد شاشة أو زر «التحديثات» داخل يومي، ولا توجد شاشة أو زر للويدجتس. الويدجتس السبعة تختارها من شاشة الهاتف الرئيسية فقط.
- قناة بيانات الإصدار العامة `android-latest.json` تُنشأ تلقائيًا في المستودع عند نشر إصدار موقع، مع استخدام GitHub Releases API كبديل عند غيابها أو اكتشاف أنها متأخرة.
- سيظل نشر إصدار APK جديد في GitHub Releases مشروطًا **بوجود مفتاح توقيع التطبيق الأصلي في GitHub Actions Secrets**، ولن نبدّله أو نرفع أسراره للمستودع. وحتى تتوفر هذه الأسرار لا يمكن الادعاء أن كل الأجهزة تتلقى تحديثات APK عامة.
- إصدارات APK القديمة التي لا تحتوي نظام التحديث الذاتي تحتاج تثبيت نسخة موقعة حديثة مرة واحدة فوق التطبيق المثبت، دون حذف بياناته.
- عند نشر يومي لاحقًا في Uptodown، يتوقف التحديث الداخلي لأجهزة ثبّتت النسخة عبر Uptodown حتى لا تتنافس قناتا التوزيع. تنزيل تحديثات Uptodown قد يتم تلقائيًا من تطبيق المتجر، بينما التثبيت يتبع آلية المتجر ونظام Android.

## إعداد التوقيع والنشر الآلي

أداة المالك Windows: `android/SETUP_SIGNING_ONCE_WINDOWS.ps1`. لا ترفع مفاتيح التوقيع أو ملف النسخة الاحتياطية إلى مستودع عام أو ترسلها في محادثة.
