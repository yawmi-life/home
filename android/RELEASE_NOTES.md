# يومي LifeOS — النسخة الموحدة Android 1.5.0

**نفس التطبيق الرئيسي:** `com.yawmilife.app`، وليس تطبيقًا منفصلًا للويدجتس.

## الجديد

- ويدجتس أندرويد الأصلية السبعة على الشاشة الرئيسية، مرتبطة بملخصات حساب يومي الحقيقية
- واجهة تطبيق واحدة تشمل تصميمات ATLAS وJOURNAL وQUEST والأقسام المعتادة
- **فحص تحديثات تلقائي** عند فتح التطبيق (بحد أقصى مرة كل 12 ساعة)، وزر «التحديثات» للتحقق الفوري، وزر «▦ الويدجتس» لطلب إضافتها لشاشة الهاتف
- **تحديث فوق التطبيق المثبّت**: عند نشر إصدار مستقر أحدث في GitHub Releases يظهر طلب تنزيل، ثم يفحص تطبيق يومي البصمة SHA-256 وشهادة توقيع APK واسم الحزمة وأن رقم الإصدار أحدث
- بعد التحقق، يفتح شاشة تثبيت تحديث Android الرسمية. Android يطلب موافقة المستخدم وقد يطلب السماح لمصدر التثبيت مرة واحدة
- **تحديث محتوى الواجهة دون APK:** عند توافر إنترنت متحقق من الاتصال يجلب التطبيق شاشات JS وCSS وHTML مباشرة من GitHub Pages عبر HTTPS، ويعود إلى النسخة المضمنة داخل APK عند عدم توافر الشبكة أو تعذر الوصول للموقع
- ملفات الواجهة الأساسية ومكتبة الدخول الموثوقة مضمّنة داخل APK، لذلك لا تعتمد شاشة البداية على متصفح خارجي

## حماية الحساب والبيانات

- لا حاجة لإزالة التطبيق أو حذف بياناته عند تثبيت تحديث يحمل نفس اسم الحزمة **ونفس شهادة التوقيع الأصلية**.
- لا يتم احتساب أي XP وهمي بسبب الويدجتس. تقرأ الويدجتس ملخصات آمنة لا تحتوي أسماء مهام أو بيانات مالية.
- تسجيل الدخول والمزامنة السحابية يتطلبان اتصال الإنترنت.
- تحديثات APK **لا تُثبت بصمت**: يمنح مستخدم Android موافقته النهائية، كما يفرض نظام أندرويد.
- لا يوافق النظام على APK يحمل توقيعًا مختلفًا أو إصدارًا أقدم، ولا يتجاوز تحذيرات Android أو Play Protect.

## خطوات تحديث النسخة الحالية

1. ثبّت APK الرسمي الموقّع بنفس الشهادة كتحديث فوق «يومي» الموجود، دون حذفه.
2. افتح يومي. يمكنك الضغط على «التحديثات» في شريط التطبيق أو تركه يتحقق عند الدخول.
3. عند توفر إصدار أحدث مستقر: «تنزيل وتحديث»، ثم وافق على رسالة التثبيت الرسمية لأندرويد.
4. الويدجتس: اضغط مطولًا على شاشة الهاتف الرئيسية ← ويدجتس ← يومي LifeOS.

## شرط إصدار APK رسمي تلقائيًا

مسار GitHub Actions `.github/workflows/yawmi-android-apk.yml` يبني إصدارًا جديدًا عند تعديل ملفات Android، لكنه **لا ينشر إصدارًا عامًا دون مفتاح التوقيع الأصلي**.
يدعم هذا المسار أحد الخيارين في أسرار GitHub Actions:
- `YAWMI_ANDROID_KEYSTORE_B64` + `YAWMI_ANDROID_KEYSTORE_PASSWORD`
- أو `YAWMI_SIGNING_RECOVERY_PRIVATE_KEY_B64` لاستعادة الهوية من الأرشيف المشفر.

لا تضع المفتاح الخاص أو كلمات مروره في ملفات المستودع أو في الدردشة. ما لم يُنشر APK موقّع في **إصدارات GitHub الرسمية** فلن يعرض التطبيق تحديثًا جديدًا، حتى لو نجحت عملية بناء تجريبية.

بصمة شهادة التطبيق الأصلي (SHA-256):
`C9:41:1A:EB:C3:83:EC:82:00:17:7D:6B:C2:AF:79:56:02:90:C4:F0:A1:03:5B:45:BA:AD:CC:F1:AF:B6:F3:D8`

ملاحظة: قدرات تنزيل الملف والتثبيت تحتاج اختبار تشغيل فعلي على جهاز Android بعد توقيع ونشر أول إصدار 1.4.0 مستقر.

## إكمال التحديث التلقائي الرسمي مرة واحدة

حتى الآن يتم بناء APK موقّع محليًا وتسليمه للمستخدم. لكي تتمكن كل نسخ يومي من اكتشاف تحديثات APK من GitHub، يجب نشر كل APK جديد كإصدار مستقر `android-vX.Y.Z` في GitHub Releases. مسار البناء الرسمي مجهز لكنه يحتاج مفتاح التوقيع الأصلي داخل **GitHub Actions Secrets**، ولا يقبل استبداله بمفتاح مختلف.

لمالكي المشروع على Windows يوجد سكربت إعداد محلي يحفظ المفتاح في GitHub Secrets بدون وضعه في المستودع أو المحادثات:
`android/SETUP_SIGNING_ONCE_WINDOWS.ps1`

هذا السكربت يحتاج نسختك الخاصة من `YAWMI_ANDROID_SIGNING_BACKUP_OWNER_ONLY.zip`، مع GitHub CLI وOpenSSL؛ ينشئ السرّين الأصليين ثم يطلق مسار نشر الإصدار الرسمي. لا ترفع ZIP الخاص بالتوقيع إلى GitHub عامةً ولا تنسخ مفاتيحه في الشات.

إذا لم تُضبط أسرار GitHub، سيظل آخر إصدار عام قديمًا ولن يكتشف نظام التحديث التطبيق الجديد. لا يمكن إجبار أندرويد على تثبيت تحديث APK بصمت؛ موافقة نظام التثبيت إلزامية.
