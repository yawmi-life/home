# يومي LifeOS V27 — تقرير التنفيذ والتحقق

التاريخ: 2026-11-04 | المستودع: yawmi-life/home | المشروع: yawmi-lifeos Supabase

## ما نُفِّذ على المصدر
- حذف One Tap Actions من كل الثيمات، ونقل تحديات الأسبوع إلى «رحلتك».
- جلسة تركيز عامة أو مربوطة بمهمة أو عادة أو هدف؛ حفظ هوية الجلسة وحالتها محليًا واستعادتها بعد إعادة الفتح لمنع الجلسات المكررة.
- فصل الرتبة الموسمية عن المستوى الدائم. عتبات الموسم: برونز 0، سيلفر 400، جولد 1200، بلاتينيوم 2500، دايموند 4000، كراون 6000، آيس 8500، كونكر 12000.
- لوحات عامة وأصدقاء، معرف YM- ثابت، إعدادات ظهور اختياري، قبول طلبات الأصدقاء، أرشيف المواسم وميداليات أول ثلاثة.
- مقارنة نقاط الموسم الحالي بالسابق، وأوسمة نشاط محفوظة دائمًا عند 5/20/60 يومًا.
- Snapshot محلي لكل حساب في IndexedDB، مسودات مؤجلة، ودمج ثلاثي للتعديلات غير المتعارضة مع عدم استبدال أحد الجهازين بالآخر عند تعارض الحقول.
- PWA: حفظ واجهة التطبيق ومكتبة Supabase العامة في Service Worker، بدون تخزين استجابات API الخاصة بالمستخدم.
- تسجيل الخروج يخفي لوحة المنافسة ويزيل ملفات أوفلاين لهذا الحساب حين يكون تسجيل الخروج صريحًا.

## ما نُفِّذ في Supabase
- جداول seasons, public_profiles, season_days, standings, season_awards, quest_awards, friend_requests مع RLS.
- صلاحيات INSERT/UPDATE/DELETE المباشرة مغلقة أمام authenticated/anon على الجداول الجديدة؛ عمليات التعديل تمر عبر RPC مصادق عليها.
- حساب نقاط موسمية خادميًا من مستند المستخدم المحفوظ، مع حد يومي 400 XP، منع تكرار task/habit ID، وتعويض الحذف.
- الموسم S01 يبدأ 2026-10-01 وينتهي قبل 2027-01-01 بتوقيت الرياض. 400 موسم مولدة إلى 2126، كل 3 أشهر.
- Cron job: yawmi_finalize_seasons_daily، الساعة 21:00 UTC (00:00 السعودية)، لإنهاء المواسم وحفظ الأوسمة.
- نظام الصداقة يشترط موافقة الطرفين ويمكن إظهار النقاط للأصدقاء المقبولين دون نشر الحساب للعالم.
- الطلبات محدودة بـ20 طلبًا خلال 24 ساعة، وإعادة الطلب بعد الرفض لها تباطؤ سبعة أيام.

## اختبار تم بنجاح
1. استدعاء ranked_sync + ranked_dashboard + quest_archive باستخدام معاملة SQL تجريبية تم التراجع عنها: S01 / Bronze / arrays.
2. فحص RLS: anon لا يستدعي RPC؛ authenticated لا يكتب مباشرة في جدول النقاط.
3. اختبار duplicate task/habit IDs: تُحتسب مرة واحدة.
4. فحص مواسم S01/S02/S100/S400 بتوقيت السعودية.
5. اختبارات threeWay: دمج تعديلات مستقلة، كشف تعارض نفس الحقل، وحذف آمن.
6. اختبار مكونات الواجهة ببيانات وهمية: لوحة الترتيب والأرشيف والهوية والاختفاء عند تسجيل الخروج.
7. فحص صحة JavaScript لملفات الواجهة والسيرفر وService Worker.

## حدود وتشغيل
- **النشر العام غير مؤكد بعد:** آخر فحص GitHub Pages كان يعرض نسخة أقدم و404 للملفات الجديدة، مع عدد كبير من عمليات Pages Build في الانتظار.
- اختبار نهاية-لنهاية على حسابين حقيقيين، وتبديل الشبكة، وفحص موبايل PWA لم يكتمل بعد؛ لا يُدَّعى أنه مكتمل.
- الوضع الأوفلاين يحتاج تثبيت التطبيق أو زيارة أونلاين سابقة وجلسة حساب صالحة مخزنة؛ تسجيل الدخول لأول مرة يحتاج إنترنت.
- المزامنة الآمنة تدمج فقط التغييرات غير المتعارضة. تعديلات نفس الحقل على جهازين تطلب مراجعة يدويًا؛ لا يجوز ادعاء حل كل التعارضات تلقائيًا.
- النقاط ذاتية التسجيل بطبيعتها، ولذلك لا يمكن منع الغش كليًا. قيود المعدل والنقاط تقلله ولا تثبت تنفيذ المهام في الواقع.
- المواسم تُغلق في Cron كل يوم عند منتصف الليل بتوقيت السعودية. الظهور العام اختياري، والمركز في أول 3 يُحتسب للظاهرين علنًا عند الإغلاق.
- Supabase Security Advisor أبلغ عن وظائف SECURITY DEFINER قابلة للاستدعاء بواسطة authenticated، وهو مقصود لهذه العمليات المصرّح بها؛ الوصول مقيّد بمعرّف auth.uid() والوظائف غير المصرّح بها ليست قابلة للاستدعاء.
- Supabase Auth leaked-password protection مُعطَّل؛ تفعيله منفصل من إعدادات Auth في لوحة Supabase.
