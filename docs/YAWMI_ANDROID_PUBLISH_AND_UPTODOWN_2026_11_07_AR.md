# يومي LifeOS — إصدار أندرويد والإشعارات والويدجتس وUptodown

## سبب رفض Uptodown
رفضت Uptodown APK باعتباره Low-quality WebView: الموقع وحده في حاوية لا يضيف وظيفة للهاتف.
أضفنا لتطبيق Android الأصلي:
- 7 AppWidgetProvider أصلية لشاشة الهاتف الرئيسية، موجودة مسبقًا في المشروع (لا أزرار ويدجت داخل يومي).
- تنبيهات Android أصلية بموافقة المستخدم: إشعار تجريبي، مهام ذات وقت وتاريخ، مواعيد التقويم والتذكيرات؛ تُجدول مع AlarmManager وتظهر بعد إغلاق التطبيق.
- استعادة جدول التنبيهات بعد إعادة التشغيل؛ بدون صلاحية exact alarm.
- واجهة تعمل دون اتصال من أصول مضمّنة، مع مزامنة الحساب السحابية عند عودة الشبكة.
- تحديثات محتوى الموقع تلقائيًا، وتحديثات APK عبر قناة الإصدار الموقّع نفسها.

**حدود الإشعارات:** تنبيهات Android هذه محلية وليست FCM push؛ لا تصل مواعيد أُنشئت في جهاز آخر حتى يُفتح يومي ويُزامن، ويمكن لأندرويد تأخير التنبيه. تنبيهات PWA الموجودة تستخدم Web Push بشكل مستقل، ولا تعمل داخل Android WebView بطريقة الاعتماد على PushManager. لا نستخدم جسر JavaScript يكشف بيانات خاصة أو سرًا.

## أصل رابط Digital Asset Links
الموقع داخل https://yawmi-life.github.io/home/ لكن شهادة ربط نطاق GitHub Pages يجب أن تكون منشورة **بدون إعادة توجيه** في:
https://yawmi-life.github.io/.well-known/assetlinks.json

الملف الأصلي الجاهز: `android/digital-asset-links/assetlinks.json`
والنسخة: `.well-known/assetlinks.json` في مستودع `yawmi-life/home` تخدم فقط `/home/.well-known/assetlinks.json`، وليست جذر المضيف.
مستودع `yawmi-life/yawmi-life.github.io` **غير موجود** ضمن مستودعات الحساب وقت المراجعة. لإنجاز هذه الخطوة:
1. أنشئ مستودعًا عامًا باسم `yawmi-life.github.io` تحت المستخدم `yawmi-life`.
2. ضع في الفرع الرئيسي ملف `.nojekyll` وملف `.well-known/assetlinks.json` باستخدام المحتوى أعلاه.
3. فعّل GitHub Pages (Deploy from a branch, `main`, `/`).
4. تأكد أن رابط الجذر يرجع `200` و `Content-Type: application/json` مباشرة، وتأكد من مطابقة SHA-256 مع شهادة **APK الموقّع النهائي** وليس debug.

**مهم:** Android WebView الحالي لا يحتاج assetlinks لحذف شريط Chrome؛ هذا الملف يُستخدم للتحقق من App Links / Trusted Web Activity. تطبيق Android الحالي يستخدم WebView أصليًا وليس TWA.

## إصدار APK قبل الرفع
1. افتح https://github.com/yawmi-life/home/actions/workflows/yawmi-android-apk.yml وشغّل/راجع أحدث بناء.
2. يجب توفير أسرار التوقيع الأصلي في GitHub Actions: `YAWMI_ANDROID_KEYSTORE_B64` + `YAWMI_ANDROID_KEYSTORE_PASSWORD`، أو مفتاح استرداد مشفر `YAWMI_SIGNING_RECOVERY_PRIVATE_KEY_B64`؛ لا تنشر أبدًا الملفات الخاصة في GitHub أو الشات.
3. انتظر اكتمال compile واختبارات smoke وراجع APK الموقع في GitHub Releases، وليس debug أو unsigned. تحقق من `com.yawmilife.app` وبصمة التوقيع الأصلية وتزايد versionCode.
4. ثبّت الإصدار الموقّع فوق إصدارك السابق **دون حذف التطبيق القديم** لحفظ البيانات، ثم من شاشة أندرويد الرئيسية اضغط مطولًا > Widgets > يومي، واختبر عدة ويدجتس.
5. داخل «تقويم يومي > إشعارات الهاتف» امنح إذن Android 13+، أرسل إشعارًا تجريبيًا، ثم أنشئ موعدًا بعد دقائق واختبره مع إغلاق التطبيق. تذكير AlarmManager ليس توقيتًا دقيقًا مضمونًا.
6. التقط لقطات شاشة حقيقية من APK الجديد تُبرز الويدجتس، أذونات وإشعارات الهاتف، المحتوى دون اتصال، والتقويم والمهام.
7. في Uptodown: راجع بيانات التطبيق، وارفع APK **الموقع والمجرّب** بدل APK v1.0.0 أو Companion beta القديم؛ في طلب مراجعة الرفض اشرح الوظائف الأصلية التي لا يقدمها الموقع.
8. القبول قرار تحرير مستقل لدى Uptodown وغير مضمون بمجرد تعديل الوصف أو الاسم.

## التحديثات
- واجهة الويب: من GitHub Pages عند فتح التطبيق على الإنترنت.
- ويدجتس وتنبيهات النظام: لا تُضاف إلى APK المثبت عبر تحديث HTML فقط؛ تتطلب APK أصليًا جديدًا يحمل النسخة والـsignature نفسها.
- التحديث الصامت مشروط بنظام Android والـinstaller، ولا يمكن إجبار كل هاتف على تحديث صامت.
- لأجهزة Uptodown مستقبلًا يجب احترام قناة تحديث المتجر وعدم فرض مسار APK مختلف.
