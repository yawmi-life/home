# يومي LifeOS V35 — التقويم الموحد، إشعارات الخلفية، بحث الكتب العربية

**التاريخ:** 5 نوفمبر 2026

**التطبيق:** https://yawmi-life.github.io/home/

## أ) دمج التذكيرات داخل التقويم وإزالة القسم المكرر

- أزلنا زر «التذكيرات والمناسبات» من الشريط الجانبي وقائمة الهاتف ومدير الأقسام ومن صفحات التصاميم الثلاثة.
- **لم نحذف** `lifeReminders` أو التذكيرات التي حفظها المستخدم. لا تزال تظهر في تاريخها داخل التقويم، مع زر «إضافة تذكير» وقائمة للتذكيرات المحفوظة وتعديلها.
- تظل أحداث `lifeCalendar` ومواعيد الفواتير والمهام والعادات في مصدرها الأصلي. لا احتساب XP إضافي.

## ب) تكامل Google Calendar — ما يعمل وما يحتاج إعدادًا خارجيًا

تمت إضافة `yawmi-google-calendar-v35.js` لتجهيز **ربط OAuth مع موافقة المستخدم**:
- بعد تكوين Google OAuth Client ID وتفعيل Google Calendar API، يمكن للمستخدم ربط Google من التقويم؛ إذن `calendar.events` يتيح قراءة وكتابة أحداث التقويم الأساسي بعد موافقته.
- جلب أحداث Google للعرض داخل تقويم يومي **من غير تغيير سجلاته المحلية**، لمدة محدودة (30 يومًا سابقة و370 يومًا قادمة، حتى 1000 حدث بكل تحديث).
- عند ضغط «تصدير مواعيد يومي إلى جوجل» مع التأكيد، ينشئ أو يحدّث المواعيد المحلية في Google باستخدام معرفات حتمية قابلة للتكرار لتقليل الازدواج. لا يحذف أحداث Google الأصلية.
- رابط «Google ↗» في كل موعد يفتح نموذج إضافة الموعد داخل Google Calendar، حتى دون ربط OAuth.
- زر «تنزيل مواعيدي ICS» متاح الآن لاستيراد المواعيد في جوجل كالندر وغيره، دون نقل بيانات تلقائي.
- **المطلوب لتنشيط OAuth:** مسؤول تطبيق يومي يجب أن ينشئ مشروع Google Cloud، ويفعّل Calendar API، ويهيئ OAuth Consent Screen، وينشئ Web OAuth Client، ويسجل أصل الموقع `https://yawmi-life.github.io` ضمن Authorized JavaScript origins، ثم يضع **Client ID العام فقط** في `window.YAWMI_CONFIG.googleCalendarClientId` بملف `config.js`. *لا تضع Google Client Secret في GitHub أو المتصفح*.
- **الوضع الحالي:** Client ID غير موجود. لذلك يظهر للمستخدم شرح واضح وحل Google direct/ICS، لكن **ربط OAuth الكامل لن يتم حتى إكمال إعداد Google Cloud**. تكامل جوجل في النسخة الحالية يدوي عند طلب المستخدم وليس مزامنة تلقائية بين الخدمات عندما يغلق التطبيق.
- Google Calendar قد يتطلب مراجعة صلاحيات التطبيق حسب قواعد Google OAuth.

المصدر: https://developers.google.com/identity/oauth2/web/guides/use-token-model

## ج) Web Push بعد إغلاق صفحة التطبيق

**منفّذ خلفية فعلي مع إشعار مشروط بتسجيل الجهاز:**
- استخدمنا Supabase Edge Function `yawmi-push-v35`، و`pg_cron + pg_net` لتشغيل فحص التذكيرات كل دقيقة.
- لا تستقبل قاعدة البيانات اشتراكات مجهولة. كل تسجيل/إلغاء/اختبار مرتبط بمستخدم مُتحقق منه، عبر `auth.getUser()` في الوظيفة.
- المفاتيح الخاصة للتوقيع VAPID محفوظة **فقط** في Supabase Vault، وليست موجودة في GitHub أو متصفح المستخدم. مفتاح VAPID العام فقط يُرسل إلى المتصفح.
- الجداول `yawmi_push_subscriptions`, `yawmi_push_sent` محمية بـRLS، وغير مكشوفة للقراءة والكتابة من دور `authenticated` العادي؛ الوصول عبر الخدمة الداخلية بعد التحقق من المستخدم.
- تُخزّن المنطقة الزمنية الصحيحة لكل جهاز. عند موعد التذكير تقارن الخدمة التوقيت محليًا في المنطقة الزمنية للمستخدم، وتمنع إرسال التنبيه نفسه أكثر من مرة لكل جهاز.
- الإشعار لا يكشف عنوان يومياتك أو مبالغك أو تفاصيل مواعيدك؛ يظهر نص عام ثم يفتح التطبيق على التقويم.
- يُشترط أن يفتح المستخدم التقويم ويضغط **«تفعيل إشعارات الجهاز»**، ويمنح الإذن؛ لا يتم تفعيل الإشعارات لمجرد تسجيل الدخول.
- بعد التسجيل، يمكنه **إرسال إشعار تجريبي**، أو إيقاف إشعارات جهازه، مع بقاء بيانات التذكيرات.
- **تنبيه التوافق:** على iPhone/iPad يلزم تثبيت PWA على الشاشة الرئيسية؛ على Android والمتصفحات المكتبية يلزم دعم Push API والخدمة العاملة. قد تؤخر إعدادات البطارية والشبكة والإذن وصول بعض التنبيهات.
- إرسال تذكيرات الخلفية لا يعني وصولًا مضمونًا 100%. أول عملية إرسال فعلية لا يمكن التحقق من وصولها دون اشتراك جهاز حقيقي وموافقة صاحبه.

الخدمة: `https://afvezxyipdytcuatragm.supabase.co/functions/v1/yawmi-push-v35`

تبعيات المصدر: `npm:web-push@3.6.7` و`npm:@supabase/supabase-js@2.118.0`.  
شيفرة الوظيفة في `supabase/functions/yawmi-push-v35/index.ts` لا تتضمن أي أسرار.

المراجع:
- https://developer.mozilla.org/en-US/docs/Web/API/Push_API
- https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers

## د) تحسين ترشيحات الكتب والبحث بالعربية

- توسيع فهرس البحث باستخدام **Google Books API بجانب Open Library**.
- عرض بيانات **الطبعة الفعلية** من Google Books: عنوان المؤلف ولغة الطبعة وعدد صفحات الطبعة والتقييمات والغلاف ونبذة الناشر إذا توفرت.
- اختيار «عربي» لا يكتفي بوجود علامة عربية على نسخة إنجليزية؛ يتأكد من أن **لغة الطبعة عربية وعنوانها مكتوب بالعربية**.
- بحث ثنائي اللغة لعناوين مختارة ذات ترجمات معروفة، مثل «العادات الذرية» ↔ `Atomic Habits`، لكن النتائج تعرض فقط بيانات طبعات حقيقية من المصدر، **دون اختلاق طبعات أو أغلفة أو نبذات**.
- عند البحث بكلمات عربية، تعطى الأولوية لنتائج لها عنوان عربي مُثبت.
- يسمح بحفظ نسخ Google Books في مكتبة المستخدم مع اسم الكتاب العربي وصورته وبيانات المصدر.
- **الحد:** لا يضمن Google Books وOpen Library وجود جميع العناوين، ولا أن يقدم الناشر نبذة بالعربية لكل طبعة. إذا لم تكن هناك نبذة عربية موثقة، يُظهر التطبيق نقص البيانات بوضوح بدل اختراع تلخيص.
- لا يتم إرسال قائمة المستخدم الشخصية أو بياناته إلى محركات البحث؛ فقط كلمات بحث الكتب العامة.

المراجع:
- https://developers.google.com/books/docs/v1/reference/volumes/list
- https://openlibrary.org/dev/docs/api/search

## الملفات الرئيسية

- `yawmi-life-core-v33.js`: دمج التذكيرات في التقويم.
- `yawmi-google-calendar-v35.js`: Google OAuth / استيراد المواعيد / تصديرها / ICS.
- `yawmi-push-v35.js`: واجهة اشتراك Web Push وإيقافه واختباره.
- `supabase/functions/yawmi-push-v35/index.ts`: خادم Push والتذكيرات المجدولة.
- `yawmi-book-discovery-v31.js`: البحث العربي الجديد متعدد المصدر، مع الحفاظ على المكتبة الحالية.
- `yawmi-extras.js`: حفظ كتب Google Books ببيانات الطبعة.
- `sw.js`: Service Worker يعرض إشعارات الخلفية ويفتح التقويم بعد الضغط.
- `config.js`: خانة Google OAuth Client ID العامة (فارغة حتى إعدادها).
- `01_ATLAS_Executive.html`, `02_JOURNAL_Editorial.html`, `03_QUEST_RPG.html`: دمج التعديلات.
- `tests/browser/life-v35.spec.cjs` و`tests/browser/books.spec.cjs`: اختبارات انحدار المتصفح.
